Subscription Analytics Platform

BigQuery dbt GCP Terraform Python
Sector Digital Publishing
Role Lead Data / Analytics Engineer
Stack GCP (BigQuery, Cloud Run, Cloud Workflows, GCS), dbt, Terraform, Python

The Challenge

A regional news publisher runs its subscription platform on WordPress and WooCommerce. Server-side tracking runs through an external tracking partner via cross-project BigQuery in the EU region. Marketing tracking runs through GA4 in a separate GCP project. These three systems were operationally disconnected: marketing had no visibility into which articles drove subscriptions; editorial had no data on which topics retained subscribers; management had no unified daily metrics.

The Requirement

Build a central data warehouse that daily:

  1. Reads subscription data from the WordPress DB (orders, subscriptions, custom fields)
  2. Pulls server-side pageviews from the tracking partner (~300k events/day, cross-region)
  3. Syncs GA4 events from the external tracking project
  4. Joins these sources in a star schema delivering conversion attribution, engagement metrics, and daily KPIs
  5. Exposes stable SQL tables to internal stakeholders (marketing, editorial, management) and external BI tools via read-only service accounts

Architecture

Medallion pattern (Bronze / Silver / Gold) on BigQuery, orchestrated via Cloud Workflows with a daily Cloud Scheduler trigger.

  • Bronze:Raw data as Parquet in GCS, with BigQuery External Tables on top. Append-only via retention policies in stg/prd.
  • Silver:1:1 staging models plus pivot/denormalization via dbt. Pre-aggregation dimensions for expensive joins.
  • Gold:Star schema with 5 fact tables (Conversions, Daily Metrics, Subscription Funnel, Article Engagement, Multi-Touch Attribution Paths). Incremental materialization with insert-overwrite partitioning.

Cross-region and cross-project data is pulled via a dedicated service account setup with minimal IAM bindings. One source had no API (legacy WordPress DB): a MySQL-via-SSH fetcher was built with a VPC connector and static egress IP so the hosting provider can maintain a reliable IP whitelist.

Highlights

  • Three-tier article attribution:Server-side tracking as primary source, WordPress paywall plugin as fallback, GA4 event param as historical tier-3 source. Attribution coverage raised from 72% to 89%.
  • Multi-touch attribution fact table:Per-touchpoint expansion of each conversion over a 30-day trace window. Five attribution weightings (first-touch, last-touch, linear, time-decay, U-shaped) stored as denormalized columns, directly usable in Looker and Power BI.
  • Buying impulse clustering:Conversions counted per 60-minute cluster rather than per order, which overstates due to failed payment retries.
  • Watermark and run registry:Custom registry enables reprocessing of individual days and dependency checks for downstream models.
  • Infrastructure as code:Fully in Terraform. Three identical environments (dev/stg/prd) plus a dedicated backfill workflow.
  • Data quality:dbt tests plus Elementary with a Slack webhook for schema drift and freshness alerts.

Results

  • Daily pipeline has run stably since go-live; current volume ~240M tracking events and ~10k daily orders
  • BI access via read-only service accounts for three stakeholder groups
  • Full tracking history backfill (2 years, ~8 TB scan) completed in one session for under $40 GCP cost
  • First marketing insights from the multi-touch model: median subscriber reads 65 articles over 12 days before converting. Single-touch attribution had hidden this entirely.
